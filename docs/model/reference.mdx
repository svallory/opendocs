## DocSet

The DocSet model represents the `opendocs.json` file - the entry point for your Documentation Set. This is the root object that contains metadata about the documentation and references all projects.

export const docSetType = {
  name: "DocSet",
  type: "object",
  description: "Root object in opendocs.json file",
  required: true,
  properties: [
    {
      name: "id",
      type: "string",
      description: "Documentation set identifier",
      required: true
    },
    {
      name: "name",
      type: "string",
      description: "Human-readable documentation name",
      required: true
    },
    {
      name: "description",
      type: "string",
      description: "Optional description of the documentation"
    },
    {
      name: "version",
      type: "string",
      description: "OpenDocs specification version"
    },
    {
      name: "projects",
      type: "Project[]",
      description: "Array of projects in this documentation set",
      required: true
    },
    {
      name: "metadata",
      type: "object",
      description: "Additional metadata (created, modified, etc.)"
    }
  ]
};

<TypeTree open {...docSetType} />

### Field Descriptions

**id** (required): Unique identifier for this documentation set. Typically matches the repository name or project name.

**name** (required): Human-readable name displayed in documentation UIs.

**description** (optional): Extended description of what this documentation covers.

**version** (optional): Version of the OpenDocs specification being used (e.g., "1.0.0").

**projects** (required): Array of Project objects. In monorepos, each package/library/app is a separate Project. Single-project repositories will have one Project.

**metadata** (optional): Additional metadata such as:
- `created`: Timestamp when documentation was generated
- `modified`: Timestamp of last modification
- `generator`: Tool information (`{ name: "extractor-name", version: "1.0.0" }`)

### Example

```json
{
  "id": "my-monorepo",
  "name": "My Monorepo",
  "description": "Documentation for all packages in My Monorepo",
  "version": "1.0.0",
  "format": "json",
  "projects": [
    { "id": "auth-service", "name": "Auth Service", "language": "typescript", "items": [] },
    { "id": "web-sdk", "name": "Web SDK", "language": "typescript", "items": [] }
  ],
  "metadata": {
    "created": "2024-01-15T10:30:00Z",
    "generator": { "name": "@opendocs/extractor-typescript", "version": "0.2.0" }
  }
}
```

## Project

The Project model represents an individual project within a Documentation Set. In monorepos, each package, library, or app is a separate Project. Each Project has its own language, version, and contains all DocItems that make up that project's API reference.

### Field Descriptions

**id** (required): Unique identifier within the DocSet. Use descriptive names like `"auth-service"` or `"web-sdk"`.

**name** (required): Display name for the project.

**language** (required): Programming language. Common values: `"typescript"`, `"javascript"`, `"python"`, `"go"`, `"rust"`, `"java"`, `"csharp"`.

**description** (optional): Project description, typically from package.json, README, or module docstring.

**version** (optional): Project version (from package.json, setup.py, go.mod, Cargo.toml, etc.).

**repository** (optional): Repository information for generating source code links:
- `type`: Repository type (`"git"`, `"svn"`, `"mercurial"`)
- `url`: Repository URL (e.g., `"https://github.com/user/repo"`)
- `fileUrlTemplate`: URL template with variables:
  - `{repo}`: Repository URL
  - `{hash}`: Git commit hash
  - `{path}`: File path from DocItem location
  - `{line}`: Line number from DocItem location
  - Example: `"{repo}/blob/{hash}/{path}#L{line}"` generates `https://github.com/user/repo/blob/abc123/src/file.ts#L42`

**items** (required): Array of top-level DocItems (modules, namespaces, packages).

**dependencies** (optional): Array of project IDs this project depends on. Enables cross-project references.

**metadata** (optional): Language-specific or project-specific metadata.

### Example

```json
{
  "id": "my-library",
  "name": "My Library",
  "language": "typescript",
  "version": "2.1.0",
  "description": "A utility library for common tasks",
  "repository": {
    "type": "git",
    "url": "https://github.com/myorg/my-library",
    "fileUrlTemplate": "{repo}/blob/{hash}/{path}#L{line}"
  },
  "items": [
    { "id": "my-library#utils", "kind": "module", "items": [] }
  ],
  "dependencies": ["shared-types"],
  "metadata": {
    "packageManager": "npm",
    "license": "MIT"
  }
}
```

## DocItem

The DocItem is the fundamental unit of documentation in OpenDocs. **Everything is a DocItem** - from entire modules down to individual method parameters. This unified approach works across all programming languages while preserving language-specific characteristics.

export const docItemType = {
  name: "DocItem",
  type: "object",
  description: "Universal documentation element",
  required: true,
  properties: [
    {
      name: "id",
      type: "string",
      description: "Language-native fully qualified name (e.g., 'pkg#Symbol', 'crate::Type', 'package.Function')",
      required: true
    },
    {
      name: "name",
      type: "string",
      description: "Human-readable name",
      required: true
    },
    {
      name: "kind",
      type: "string",
      description: "Language-specific item type (\"class\", \"rust-trait\", \"go-receiver-method\")",
      required: true
    },
    {
      name: "language",
      type: "string",
      description: "Source language",
      required: true
    },
    {
      name: "location",
      type: "Location",
      description: "Source code location",
      properties: [
        {
          name: "path",
          type: "string",
          description: "File path relative to project root",
          required: true
        },
        {
          name: "number",
          type: "number",
          description: "Line number (1-indexed)",
          required: true
        },
        {
          name: "column",
          type: "number",
          description: "Column number (1-indexed)"
        }
      ]
    },
    {
      name: "docBlock",
      type: "DocBlock",
      description: "Documentation content"
    },
    {
      name: "relations",
      type: "Relations",
      description: "Code relationships (container, extends, implements, etc.)",
      properties: [
        {
          name: "<relationship-kind>",
          type: "string | Relation | Relation[]",
          description: "DocItem ID (string), Relation object, or array of Relations"
        }
      ]
    },
    {
      name: "metadata",
      type: "object",
      description: "Language-specific metadata (includes signature info)"
    },
    {
      name: "items",
      type: "DocItem[]",
      description: "Child items (methods, properties, nested types)",
      properties: []
    }
  ]
};

<TypeTree open {...docItemType} />

### Field Descriptions

**id** (required): Language-native fully qualified name. Use each language's natural naming convention:

| Language | Format | Example |
|----------|--------|---------|
| TypeScript/JavaScript | `package#export` or `package#Class#member` | `my-lib#Calculator#add` |
| Rust | `crate::module::Type` | `serde::de::Deserialize` |
| Go | `package.Type` or `package.Function` | `fmt.Printf` |
| Python | `module.Class.method` | `mylib.Calculator.add` |
| Java | `package.Class.method` | `com.example.Calculator.add` |

**name** (required): Simple name without package/module prefix. For `mylib.Calculator.add`, the name is `"add"`.

**kind** (required): Language-specific item type. Use descriptive kinds that reflect the language:
- Common: `"class"`, `"interface"`, `"method"`, `"function"`, `"property"`, `"parameter"`
- TypeScript: `"enum"`, `"enumMember"`, `"typeAlias"`, `"constructor"`
- Rust: `"trait"`, `"impl"`, `"struct"`, `"enum-variant"`
- Go: `"struct"`, `"interface"`, `"receiver-method"`
- Python: `"class"`, `"function"`, `"method"`, `"module"`

**language** (required): Programming language of this item. Usually matches the Project language.

**location** (optional but recommended): Source code location:
- `path`: File path relative to project root (e.g., `"src/calculator.ts"`)
- `number`: Line number where item is defined (1-indexed)
- `column`: Column number (1-indexed, optional for simple line-level links)

**docBlock** (optional): DocBlock object containing documentation content. See [DocBlock](#docblock) section.

**relations** (optional): Map of relationships to other DocItems. See [Relations](#relations) section.

**metadata** (optional): Language-specific metadata. Common fields:
- `visibility`: `"public"`, `"private"`, `"protected"`, `"internal"`
- `signature`: Function/method signature with parameters and return type
- `isStatic`, `isReadonly`, `isAbstract`: Boolean flags
- `type`: Type information for properties/variables
- Language-specific: `associatedTypes` (Rust), `receiver` (Go), `decorators` (Python)

**items** (optional): Child DocItems. Examples:
- Class contains methods, properties, constructors
- Module contains classes, functions, types
- Interface contains method signatures, properties
- Enum contains enum members

### Example

```json
{
  "id": "my-package#Calculator",
  "name": "Calculator",
  "kind": "class",
  "language": "typescript",
  "location": {
    "path": "src/calculator.ts",
    "number": 10,
    "column": 1
  },
  "docBlock": {
    "description": "Performs arithmetic calculations",
    "tags": { "since": ["1.0.0"] }
  },
  "relations": {
    "container": "my-package#utils",
    "implements": ["my-package#ICalculator"]
  },
  "metadata": {
    "visibility": "public",
    "isAbstract": false
  },
  "items": [
    {
      "id": "my-package#Calculator#add",
      "name": "add",
      "kind": "method",
      "language": "typescript",
      "location": { "path": "src/calculator.ts", "number": 15, "column": 3 },
      "relations": { "container": "my-package#Calculator" },
      "docBlock": {
        "description": "Adds two numbers",
        "tags": {
          "param": [
            { "name": "param", "content": "First number", "parameters": { "name": "a" } },
            { "name": "param", "content": "Second number", "parameters": { "name": "b" } }
          ],
          "returns": ["The sum"]
        }
      },
      "metadata": {
        "visibility": "public",
        "isStatic": false,
        "signature": {
          "parameters": [
            { "name": "a", "type": { "name": "number" } },
            { "name": "b", "type": { "name": "number" } }
          ],
          "returnType": { "name": "number" }
        }
      }
    }
  ]
}
```

## DocBlock

DocBlock represents structured documentation content extracted from source code comments. It provides a unified format for documentation regardless of the original comment syntax (TSDoc, Javadoc, rustdoc, etc.).

export const docBlockType = {
  name: "DocBlock",
  type: "object",
  description: "Documentation content structure",
  properties: [
    {
      name: "description",
      type: "string",
      description: "Main description text"
    },
    {
      name: "tags",
      type: "Record<string, (string | DocTag)[]>",
      description: "Documentation tags (@param, @returns, etc.)"
    },
    {
      name: "deprecated",
      type: "DeprecatedInfo",
      description: "Deprecation information",
      properties: [
        {
          name: "message",
          type: "string",
          description: "Deprecation message",
          required: true
        },
        {
          name: "since",
          type: "string",
          description: "Version when deprecated"
        }
      ]
    }
  ]
};

<TypeTree open {...docBlockType} />

### Field Descriptions

**description** (optional): Main documentation text. Supports Markdown formatting.

**tags** (optional): Map of tag names to arrays of tag values. Format: `Record<string, (string | DocTag)[]>`
- Key: Tag name without `@` (e.g., `"param"`, `"returns"`, `"since"`)
- Value: Array of strings (simple tags) or DocTag objects (complex tags)
- Each tag type can have multiple entries (e.g., multiple `@param` tags)

**deprecated** (optional): Structured deprecation information:
- `message`: Deprecation message and migration guidance
- `since`: Version when item was deprecated

### Tags Format

**Simple tags** (just strings):
```json
{
  "tags": {
    "since": ["1.0.0"],
    "author": ["John Doe", "Jane Smith"],
    "internal": ["true"]
  }
}
```

**Complex tags** (DocTag objects):
```json
{
  "tags": {
    "param": [
      {
        "name": "param",
        "content": "The width of the rectangle",
        "parameters": { "name": "width", "type": "number" }
      },
      {
        "name": "param",
        "content": "The height of the rectangle",
        "parameters": { "name": "height", "type": "number" }
      }
    ],
    "returns": ["The calculated area"]
  }
}
```

**Mixed tags**:
```json
{
  "tags": {
    "param": [
      { "name": "param", "content": "First parameter", "parameters": { "name": "a" } }
    ],
    "returns": ["Return value"],
    "since": ["2.0.0"],
    "author": ["Developer Name"]
  }
}
```

### Example

```json
{
  "description": "Calculates the area of a rectangle.\n\nThis function multiplies width by height to compute area.",
  "tags": {
    "param": [
      {
        "name": "param",
        "content": "The width in meters",
        "parameters": { "name": "width", "type": "number" }
      },
      {
        "name": "param",
        "content": "The height in meters",
        "parameters": { "name": "height", "type": "number" }
      }
    ],
    "returns": ["The area in square meters"],
    "since": ["1.0.0"],
    "example": ["calculateArea(5, 10) // => 50"]
  },
  "deprecated": {
    "message": "Use calculateRectangleArea() instead",
    "since": "2.0.0"
  }
}
```

## DocTag

DocTag represents individual documentation tags. It supports both simple string values and complex parameter structures for tags like `@param`, `@returns`, and `@deprecated`.

export const docTagType = {
  name: "DocTag",
  type: "object",
  description: "Complex documentation tag with parameters",
  properties: [
    {
      name: "name",
      type: "string",
      description: "Tag name without @",
      required: true
    },
    {
      name: "content",
      type: "string",
      description: "Tag content",
      required: true
    },
    {
      name: "parameters",
      type: "Record<string, string>",
      description: "Tag parameters for complex tags (name, type, etc.)"
    }
  ]
};

<TypeTree open {...docTagType} />

### Field Descriptions

**name** (required): Tag name without the `@` symbol. Examples: `"param"`, `"returns"`, `"throws"`, `"deprecated"`.

**content** (required): The main content/description for this tag.

**parameters** (optional): Additional structured parameters specific to the tag type:
- For `@param`: `{ "name": "paramName", "type": "string" }`
- For `@throws`: `{ "type": "ErrorType" }`
- For custom tags: Any key-value pairs needed

### Cross-Format Normalization

Different documentation formats use different syntax, but all normalize to the same DocTag structure:

#### TSDoc → DocTag

**Source:**
```typescript
/**
 * @param width - The width of the rectangle
 * @param height - The height of the rectangle
 * @returns The calculated area
 */
```

**Normalized:**
```json
{
  "tags": {
    "param": [
      { "name": "param", "content": "The width of the rectangle", "parameters": { "name": "width" } },
      { "name": "param", "content": "The height of the rectangle", "parameters": { "name": "height" } }
    ],
    "returns": ["The calculated area"]
  }
}
```

#### Javadoc → DocTag

**Source:**
```java
/**
 * @param width the width of the rectangle
 * @param height the height of the rectangle
 * @return the calculated area
 */
```

**Normalized:**
```json
{
  "tags": {
    "param": [
      { "name": "param", "content": "the width of the rectangle", "parameters": { "name": "width" } },
      { "name": "param", "content": "the height of the rectangle", "parameters": { "name": "height" } }
    ],
    "returns": ["the calculated area"]
  }
}
```

#### Python Docstrings → DocTag

**Source (Google style):**
```python
"""
Args:
    width (float): The width of the rectangle
    height (float): The height of the rectangle

Returns:
    float: The calculated area
"""
```

**Normalized:**
```json
{
  "tags": {
    "param": [
      { "name": "param", "content": "The width of the rectangle", "parameters": { "name": "width", "type": "float" } },
      { "name": "param", "content": "The height of the rectangle", "parameters": { "name": "height", "type": "float" } }
    ],
    "returns": ["The calculated area"]
  }
}
```

#### Rustdoc → DocTag

**Source:**
```rust
/// # Arguments
/// * `width` - The width of the rectangle
/// * `height` - The height of the rectangle
///
/// # Returns
/// The calculated area
```

**Normalized:**
```json
{
  "tags": {
    "param": [
      { "name": "param", "content": "The width of the rectangle", "parameters": { "name": "width" } },
      { "name": "param", "content": "The height of the rectangle", "parameters": { "name": "height" } }
    ],
    "returns": ["The calculated area"]
  }
}
```

This standardization enables consistent rendering, template compatibility, and cross-format documentation migration.

## Relation

Relation represents a typed relationship between DocItems, supporting both simple string references and complex relationship metadata.

export const relationType = {
  name: "Relation",
  type: "object",
  description: "Typed relationship to another DocItem",
  properties: [
    {
      name: "kind",
      type: "string",
      description: "Relationship type (container, extends, implements, etc.)",
      required: true
    },
    {
      name: "target",
      type: "string",
      description: "Target DocItem ID (language-native FQN)",
      required: true
    },
    {
      name: "metadata",
      type: "object",
      description: "Relationship-specific metadata (e.g., derived: true for Rust traits)"
    }
  ]
};

<TypeTree open {...relationType} />

### Field Descriptions

**kind** (required): Type of relationship. Use descriptive, language-appropriate names.

**target** (required): The ID of the related DocItem (must be a valid language-native FQN).

**metadata** (optional): Additional context for the relationship. Examples:
- Rust trait implementations: `{ "derived": true }` for `#[derive(Trait)]`
- Generic constraints: `{ "constraint": "where T: Clone" }`
- Implementation details: `{ "explicit": true }` vs inferred

### Relations

The `relations` field in DocItem uses a `Record<string, string | Relation | Relation[]>` structure that supports three formats:

#### 1. Simple String (Most Common)

For straightforward relationships, just use the target ID:

```json
{
  "relations": {
    "container": "my-package#MyModule",
    "extends": "my-package#BaseClass"
  }
}
```

#### 2. Relation Object (With Metadata)

For complex relationships that need additional context:

```json
{
  "relations": {
    "rust-trait-impl": {
      "kind": "rust-trait-impl",
      "target": "serde::Serialize",
      "metadata": { "derived": true }
    }
  }
}
```

#### 3. Array of Relations

When an item has multiple relationships of the same type:

```json
{
  "relations": {
    "implements": [
      "my-package#IInterface1",
      "my-package#IInterface2"
    ]
  }
}
```

**Can also be array of Relation objects:**
```json
{
  "relations": {
    "implements": [
      {
        "kind": "implements",
        "target": "my-package#IInterface1",
        "metadata": { "explicit": true }
      },
      {
        "kind": "implements",
        "target": "my-package#IInterface2",
        "metadata": { "explicit": false }
      }
    ]
  }
}
```

### Common Relationship Types

**Universal:**
- `container`: Parent module, class, namespace, or package
- `extends`: Class inheritance or interface extension
- `implements`: Interface implementation

**TypeScript/JavaScript:**
- `type-reference`: References to type definitions
- `export-from`: Re-exports from other modules

**Rust:**
- `rust-trait-impl`: Trait implementation
- `rust-associated-type`: Associated type in trait
- `rust-supertrait`: Trait bound

**Go:**
- `go-receiver-type`: The type a method is defined on
- `go-embedded-type`: Embedded struct/interface

**Python:**
- `python-decorator`: Applied decorators
- `python-metaclass`: Class metaclass

### Example

```json
{
  "id": "my-lib#MyClass",
  "name": "MyClass",
  "kind": "class",
  "relations": {
    "container": "my-lib#myModule",
    "extends": "my-lib#BaseClass",
    "implements": ["my-lib#IInterface1", "my-lib#IInterface2"],
    "rust-trait-impl": {
      "kind": "rust-trait-impl",
      "target": "serde::Serialize",
      "metadata": { "derived": true }
    }
  }
}
```

## Best Practices

### For Extractor Developers

1. **Always include source locations** - Enables "Go to Definition" and source linking
2. **Use language-native IDs** - Follow each language's naming conventions
3. **Normalize documentation** - Convert language-specific docs to DocBlock format
4. **Preserve language-specific metadata** - Use the metadata field for language features
5. **Use descriptive kinds** - `"rust-trait"` is clearer than `"trait"`
6. **Link items via relations** - Always include `container` relation at minimum

### For Integrators

1. **Handle all three relation formats** - Simple string, Relation object, and arrays
2. **Support optional fields** - Not all items will have location, docBlock, etc.
3. **Render DocBlock tags consistently** - The Record format works for all languages
4. **Use IDs for cross-references** - IDs are stable, names may conflict
5. **Respect language-specific kinds** - Display TypeScript "interface" differently than Go "interface"
