## Introduction

These are actual outputs from OpenDocs extractors running on real sandbox projects. Each example demonstrates how the same Calculator library is represented in different languages while following the same model structure.

**What to notice:**
- Same six-component structure across all languages
- Language-native ID formats (`package#Symbol` vs `package.Type` vs `module.Class.method`)
- Consistent DocBlock and tag structure
- Language-specific metadata (signatures, visibility, type information)

## Cross-Language Patterns

Despite different syntax and conventions, all three languages share the same OpenDocs structure:

### Common Structure
```
DocSet
└── Project (with language specified)
    └── Items (top-level: modules/packages)
        ├── Calculator (class/struct)
        │   ├── add (method)
        │   ├── subtract (method)
        │   └── multiply (method)
        ├── Config (interface/struct/class)
        ├── LogLevel (enum/typeAlias/class)
        └── Functions (greet, formatCurrency)
```

### ID Conventions
| Language | Container | Class | Method | Function |
|----------|-----------|-------|--------|----------|
| TypeScript | `test-library` | `test-library#Calculator` | `test-library#Calculator#add` | `test-library#greet` |
| Go | `testlibrary` | `testlibrary.Calculator` | `testlibrary.Calculator.Add` | `testlibrary.Greet` |
| Python | `calculator` | `calculator.Calculator` | `calculator.Calculator.add` | `calculator.greet` |

### Common Relations
All three use `"container"` to link items to their parent:
- Methods relate to their class/struct
- Top-level items relate to their package/module
- This enables navigation up the hierarchy

### Consistent Documentation
All three normalize documentation to the same structure:
```json
{
  "docBlock": {
    "description": "Main description",
    "tags": {
      "param": [
        { "name": "param", "content": "desc", "parameters": { "name": "paramName" } }
      ],
      "returns": ["Return value description"]
    }
  }
}
```

### Language-Specific Metadata
Each language includes relevant metadata in the `metadata` field:
- **TypeScript**: `isStatic`, `isReadonly`, `isOptional`, full signature
- **Go**: `visibility`, signature at top level
- **Python**: `visibility` based on naming conventions, type hints from annotations
